Design Notes

Key design decisions:

  • Edit where you see the problem. The Recordings page IS the editor. No more "go to Manage > Rename".
  • Filename segments are clickable. Chapter number, name, and tags are interactive — click to edit in place.
  • Batch toolbar is contextual. Only appears when files are selected. Sticky so it follows your scroll.
  • Chapter split is visual. Dashed amber line shows exactly where the break will happen. Removable with one click.
  • Full preview, every file. Not 5-of-N — every single change listed with its associated files (shadow, transcripts).
  • Smart transcript handling. Green dot = just rename the files (instant). Amber dot = audio changed, must re-transcribe. Renaming chapter/name/tags should NEVER trigger re-transcription — it's a filename change, not an audio change.
  • 30-second undo. Every batch operation is reversible. This is the trust mechanism.
  • Pending changes shown inline. Old name → new name visible on each row before you commit. No surprises.
  • Manage panel still exists for Regen, Gling/Edit, AWB, Relay, Sync — just not for rename/renumber anymore.

What this replaces:

  • RenamePanel (Manage sidebar) → inline rename on Recordings page
  • ChapterListPanel (Manage sidebar) → click chapter numbers directly
  • RenameLabelModal → inline name editing
  • "(Use Manage panel to rename)" hint → gone, you just do it here

Server changes needed:

  • POST /api/manage/split-chapter — new endpoint: takes chapter + split-at-sequence, moves files ≥ sequence to next chapter, renumbers
  • Rename without re-transcribe — modify renameRecording() to rename transcript/shadow files in-place instead of delete+regenerate when only the filename (not audio) changed
  • POST /api/manage/bulk-rename — add undo support: return enough info to reverse the operation
  • Batch preview endpoint — dry-run mode that returns what would change without doing it (or compute client-side)
